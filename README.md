# 知识笔记 / Knowledge Notes

Astro 静态知识库，保留原站星空 / 地球横幅、灰白背景、蓝色链接及卡片风格。无数据库，无运行时后端；Pagefind 搜索索引与所有字体、公式资源一并部署。

## 本地开发

需要 Node.js >= 22.23.4，推荐 Node.js 24 LTS。

```sh
npm ci
npm run dev
npm run check
npm test
npm run build
npm run preview
```

**日常编辑 Markdown 使用 `npm run dev`**：它监听源文件变化，自动重新渲染 / 刷新。`npm run preview` 只提供上一次 `npm run build` 生成的静态文件，**不会监听 Markdown，也不会自动构建**；修改后只刷新 preview 页面不会更新。

验证发布效果和全文搜索时，先运行 `npm run build`，成功后再运行 `npm run preview`。开发模式不生成搜索索引，搜索页会说明原因。生产构建最后会检查本地链接、双语路由、首页卡片、占位页与输出中的元信息。

## 内容目录

```text
src/content/docs/
  00-index.zh.md
  00-index.en.md
  01-computer-science/
    00-index.zh.md
    00-index.en.md
    09-ai-ml/
      00-index.zh.md
      00-index.en.md
      01-traditional-machine-learning/
        00-index.zh.md
        00-index.en.md
        01-supervised-learning/
          00-index.zh.md
          00-index.en.md
          01-linear-regression.zh.md
          01-linear-regression.en.md
```

以上为本次发布的内容。其他主题和笔记可以继续按同一规则添加；尚未提交的本地内容不会包含在 GitHub Pages 部署中。

- 文件与目录使用小写 ASCII kebab-case，URL 稳定且不依赖翻译标题。
- 根目录及每层文件夹至少需要一种语言的 `index`。空目录可以只有 `index`。
- 中文、英文通过相同路径的 `.zh.md` / `.en.md` 配对。
- 文件名与文件夹名均可带 `序号-` 前缀，推荐从 `00、01、02…` 连续编号。每一层的文件夹和文档在同一个序列中排序，例如 `01-complexity.zh.md`、`02-trees/`、`03-sorting.zh.md`。序号只控制顺序，不出现在页面标题、URL、侧边栏、路径展示或搜索结果中。
- 支持任意位数和混合补零：`01` 与 `001` 都表示 1；`02`、`010`、`100` 按数值排序为 2、10、100，不按字符串或浮点数比较。位数不必统一，但本地文件管理器按名称排序时，统一补零更方便。
- 同一正文的中英文件必须使用相等的数字序号（允许补零位数不同），或同时不编号；同一逻辑文件夹也需要相等的目录序号。index 文件自身的编号不参与排序，统一推荐 `00`。不同项目可以使用相同序号，此时按去掉序号后的路径排序；未编号的项目排在已编号项目之后。
- 文件夹在父目录中的顺序只由**文件夹名**的编号决定，不再由其 index 的编号决定；每层 index 统一推荐使用 `00-index.zh.md` / `00-index.en.md`。index 是当前文件夹的入口，不参与其内部子文档排序。无编号的文件夹和文档均排在有编号项目之后。
- 系统为两种语言生成 `/zh/.../` 与 `/en/.../`。缺译时生成明确的占位页及原文链接，不复制正文，也不加入搜索或笔记列表。
- `notes`、`tags`、`search` 是保留的顶层路由。叶子文档与目录不能占用同一个路径。
- 新增 Markdown 后自动加入目录树，无需修改导航配置。

### 知识领域与主题

内容采用“领域 → 主题 → 文档 / 子目录”层级。`docs` 下第一层文件夹是知识领域，例如 `01-computer-science`；该领域的下一层文件夹是主题，例如 AI/ML、硬件、操作系统。计算机内容与中英领域首页放在 `01-computer-science` 下，`docs/00-index` 是全站入口。

将来增加其他领域时，在 `docs` 下新增同级文件夹（例如 `02-mathematics`），加入该领域至少一种语言的 `00-index`，再添加主题文件夹及其 index 即可。不需要改代码或手写导航配置。

顶部为每个领域生成一个下拉入口：目前只有“计算机知识笔记”，以后会自动出现其他领域。下拉菜单包含领域首页及其主题，不混入其他领域的主题。桌面可悬浮展开，手机可点击；键盘可用 Enter / Space 展开、方向键进入菜单、Escape 收起。关闭 JavaScript 后仍可点击展开。搜索、语言与主题工具保留在右侧，“全部笔记”和“标签”入口位于页脚。

全站首页展示领域大卡片；领域首页展示其主题大卡片。两级首页都没有左右侧栏或手机目录按钮，桌面两列、手机单列，并读取各自 index 的标题、描述与 Markdown 简介。

进入主题后，左侧目录以该主题为根，只显示它及其子文档 / 子目录。例如算法主题下所有页面的侧栏都以“算法与数据结构”为根，不会扩大为整个计算机领域。直接访问、刷新、语言切换和缺译占位页保持一致，手机使用同一目录。直接放在领域下的正文使用该领域的目录。搜索、标签和全部笔记为全站页面，仍展示全站目录。

领域内横幅保留该领域的中英标题，并链接至领域首页；全站页面显示“知识笔记 / Knowledge Notes”。返回全站首页可使用面包屑或页脚链接。

URL 包含去掉编号后的领域路径，例如 `/zh/computer-science/hardware/`、`/en/computer-science/algorithms/complexity/`。此次迁移不生成旧地址跳转；请改用带领域前缀的新地址。

### Frontmatter

```yaml
---
title: 复杂度分析
description: 一句话说明本页主题。
tags: [算法, 复杂度]
published: "2026-11-04"
---
```

`title`、`description` 必填；其余可选。`published` 必须是加引号的有效 `YYYY-MM-DD` 日期。标签可以按语言分别编写。目录页也可带标签，但标签汇总与“全部笔记”只统计非目录正文。

排序由文件名 / 文件夹名的数字前缀决定，不再使用 frontmatter `order`；继续填写 `order` 会让构建报错，避免两套顺序冲突。顶部分类菜单、目录卡片与侧边栏共用此顺序；上一篇 / 下一篇按同一棵目录树深度优先排列，包含目录及缺译占位页。按日期排列的“全部笔记”列表不受序号影响。

领域下的主题文件夹自动作为分类，内部使用包含领域的完整路径区分不同领域的同名主题，筛选项显示“领域 / 主题”；直接放在领域下的正文以领域作为分类。“全部笔记”汇总所有领域，按 `published` 倒序，未设置时使用该语言文件的 Git 首次添加日期；无提交记录的文件明确标记并排在最后。该列表支持可分享的分类与标签过滤参数。

### Markdown

页面标题来自 `title`，正文请从 `##` 开始，`##` 与 `###` 自动进入页内目录。支持围栏代码高亮和复制、表格、`$...$` 行内公式、`$$...$$` 独立公式。

文档间推荐使用带语言后缀的相对 Markdown 链接，例如：

```md
[复杂度分析](../01-complexity.zh.md)
[地址空间](../../02-operating-systems/01-virtual-memory.zh.md#地址空间是一种抽象)
```

构建从路径的**每一层文件夹和文件名**中去掉序号，按逻辑路径解析链接，再转换为网页 URL；也可以写不带序号的稳定链接，例如 `../complexity.zh.md` 或 `../../operating-systems/virtual-memory.zh.md`。因此修改任意层的编号或从 `01` 扩展为 `001` 都不会改变 URL，也不会破坏现有 Markdown 链接。若目标语言文件尚缺但另一种语言存在，则链接到自动生成的占位页。两种语言都不存在、命名不合规或越过内容根目录的目标会让构建失败。图片等静态资源可放在 `public/images/`，正文使用 `/images/filename.png`。不要把本机文件路径写入正文。

## 双语与搜索

访问 `/` 时优先读取用户已选语言，否则使用浏览器首选语言：中文变体进入中文，其余进入英文。语言选择在当前浏览器本地保存；直接访问 `/zh/.../` 或 `/en/.../` 始终尊重 URL，不强制跳转。禁用 JavaScript 后仍能手动选择语言和浏览全部静态文档。

搜索默认只返回当前语言的真实内容。搜索页可切换搜索语言并保留查询词。搜索不请求第三方服务，也不索引缺译占位页。

## 构建和 Git 信息

- 每页页脚显示整站本次构建时间（UTC）与部署源码 commit。
- 文档显示该语言 Markdown 最近一次 Git 提交时间及 commit；模板、样式变化不冒充正文更新。
- 搜索、标签、时间列表等生成页面显示对应页面模板的 Git 更新记录；根入口及 404 页面提供双语记录。它们的数据刷新版本仍以整站构建信息为准。
- 本地未提交修改会明确标记为“未提交”，无历史文件不会伪造 Git 时间或 commit。
- 缺译页没有自己的 Markdown 历史，明确显示“尚无译文，无独立更新记录”。
- Git 命令失败会中止构建，不会默默生成看似正常的元信息。工作流使用完整历史 `fetch-depth: 0`。
- 示例 `published` 是显式发布日期，不代表历史提交时间。

## GitHub Pages

工作流在 `master` 推送时检查、测试、构建，并通过 GitHub Pages artifact 部署；PR 只验证，不发布。

首次启用时，在仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。站点地址为 https://johnnyjiang1.github.io 。仅生成的 `dist` 部署到 Pages，源工程无需放在发布分支。

网站重建保留现有 Git 历史。若以后需要重置历史，应先保留旧历史备份，再单独确认远端改写范围。
